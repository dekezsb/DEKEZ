# DEKEZ document numbering

New style for every system-generated document: `<PREFIX><YY><MM>-<NNN>`, e.g. `PV2611-001`.
The running number restarts at 001 each month per prefix, based on the document date.
Numbers come from `public.next_document_number(prefix, date)` (atomic upsert on
`document_number_counters`), so concurrent users never get the same number and voided
numbers are never reused. After 999 in a month the number simply grows (`PV2611-1000`).

Existing numbers are **not** rewritten. Migration `20261127090000_document_numbering_aliases.sql`
stores a new-style alias for each one in `document_number_aliases` (searchable in the Voucher Register).

| Document | Where generated | Old example | New example | Prefix | Month taken from |
|---|---|---|---|---|---|
| Rental invoice | trigger `set_rental_invoice_metadata` on `rent_bills` | `DINV-2026-1282` | `DINV2611-001` | DINV | bill month |
| Manual journal (also renovation invoice journals, which post through it) | `post_manual_journal_entry` | `JE-20261019-B76EB5AC` | `JE2611-001` | JE | entry date |
| Payment voucher (new Voucher module) | `post_accounting_voucher` | — | `PV2611-001` | PV | voucher date |
| Receipt voucher (new) | `post_accounting_voucher` | — | `RV2611-001` | RV | voucher date |
| Journal voucher (new) | `post_accounting_voucher` | — | `JV2611-001` | JV | voucher date |
| Bank-reconciliation payment voucher | `record_bank_expense_voucher` | `PV-20261030-90F4632C…` | `PV2611-002` (shares the PV counter) | PV | bank line date |
| Renovation quotation | `issue_renovation_document_base` | `DQ-2026-000001` | `DQ2611-001` | DQ | document date |
| Renovation invoice | `issue_renovation_document_base` | `DRI-2026-000004` | `DRI2611-001` | DRI | document date |
| Historical credit reclassification journal | `clear_historical_rental_credits` | `HRC-<uuid>` | `HRC2611-001` | HRC | posting day |
| Maintenance ticket | column default on `maintenance_tickets` | `DKZ-FD80939D` | `DKZ2611-001` | DKZ | submission date (MYT) |
| Checkout deposit settlement journal (maintenance fee) | not generated by repo code (one-off/import) | `JE-DM-20260905-A2421F50` | alias `JEDM2609-001` | JEDM | entry date |
| Checkout deposit settlement journal (forfeit) | not generated by repo code (one-off/import) | `JE-DF-20260904-79D645C0` | alias `JEDF2609-001` | JEDF | entry date |

Not changed (not document numbers):
- `receipts.receipt_number` – table exists but has no rows and no generator.
- `tenant_referral_codes.referral_code` (`DEKEZ-xxxxxxxx` / phone numbers) – codes tenants type, not documents.
- `BANK-xxxxxxxx` – placeholder bank reference used only when a bank line has no reference.
- `ITEM-…` renovation catalogue item codes, supplier receipt numbers on expenses, bank references.
- `rental_invoice_audit_logs.invoice_number` – audit copy, never rewritten.

Counters are global (one company today). If DEKEZ ever runs several companies on one
database, add `company_id` to `document_number_counters`.
